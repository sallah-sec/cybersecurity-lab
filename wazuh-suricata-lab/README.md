# Wazuh & Suricata SIEM Lab

## Overview
This lab demonstrates the deployment and configuration of a Security Information and Event Management (SIEM) stack using **Wazuh** for endpoint security and **Suricata** for network intrusion detection (NIDS). 

The environment consists of a Wazuh Manager (Ubuntu Server), a Wazuh Agent (Windows 10), and Suricata monitoring network traffic. The following screenshots highlight the key outcomes of the lab, including endpoint visibility, vulnerability assessment, and network alerting.

---

## 1. Wazuh Dashboard Overview
![Wazuh Dashboard Overview](images/wazuh-dashboard.png)

**Description:**
This image shows the main Wazuh dashboard summarizing the health of the environment. 
*   **Agent Status:** Confirms the successful connection of the Windows 10 endpoint (`SurfaceGo-Win10`).
*   **Alert Severity:** Displays the breakdown of alerts over the last 24 hours (Medium and Low severity), indicating active monitoring.
*   **Security Operations:** Highlights the modules enabled, including Malware Detection, File Integrity Monitoring (FIM), and MITRE ATT&CK mapping.

---

## 2. Vulnerability Detection Dashboard
![Vulnerability Detection](images/vulnerability-scan.png)

**Description:**
This view demonstrates the Vulnerability Detection module in action.
*   **Critical Findings:** The dashboard reveals **52 Critical** and **433 High** severity vulnerabilities detected on the Windows 10 agent.
*   **Top Packages:** Identifies the specific software contributing to the risk, notably `Microsoft Windows 10 Pro` and `Google Chrome`.
*   **Actionable Insight:** This allows a security analyst to prioritize patching efforts based on the highest risk (Critical CVEs) rather than guessing.

---

## 3. Suricata Network Alerts (fast.log)
![Suricata Alerts](images/suricata-alerts.png)

**Description:**
This terminal screenshot displays the `/var/log/suricata/fast.log` file, showing real-time network intrusion alerts generated by Suricata.
*   **Detection:** The logs indicate repeated "SURICATA Ethertype unknown" alerts (Priority 3). 
*   **Analysis:** While these specific alerts are often benign (e.g., non-IP traffic like ARP or LLDP), this view proves that the Suricata IDS engine is actively inspecting traffic and successfully writing alerts to the log file for analysis by the SIEM.
